# WTC tenant dataset

Source: CNN.com, "List of World Trade Center tenants" (tenant list provided by
CoStar Group, Inc.), six pages captured by the Internet Archive on 2001-09-13.
Raw captures live in this folder as cnn_t1.html, cnn_t2.html, cnn_t4.html,
cnn_t5.html, cnn_t6.html, cnn_t7.html (one page per building; there is no
building 3 page). Original page URLs, reconstructed from links inside the files:
http://www.cnn.com/SPECIALS/2001/trade.center/tenants<n>.html (paradata P-019).
The files carry no Wayback toolbar or rewritten archive links, so the capture URL
is not yet recorded (P-020).

The list is CNN's and CoStar's. We cite it; we do not own it.

## Files

| File | What it is | Generated by |
|---|---|---|
| cnn_t*.html | Raw archived pages. Never edited. | (source) |
| tenants.clean.json | Canonical tenant records, one per data row of the six tables, schema in SCHEMA.md. | scripts/parse-cnn.ts |
| paradata.json | Every interpretive call the parser made, with what was rejected and why (London Charter). P-001 is the lead's schema decision; P-010 onward are the parser's. | scripts/parse-cnn.ts (P-010+) |
| wtc_tenants.json | Superseded first extraction (see defect list). Kept only for diffing; do not build on it. | earlier whitespace-tokenising pass |

Regenerate and check:

    node --experimental-strip-types scripts/parse-cnn.ts
    node --experimental-strip-types scripts/validate-tenants.ts

The validator exits non-zero if row counts disagree with the HTML, any field is
not verbatim from its cell, sq_ft does not parse, or a floor token is neither an
integer nor a known code.

## Evidence level

All 329 rows are `documented` (contemporaneous listing), paradata P-017. The
earlier note that eight tenants were "validated against independently sourced
facts" (Cantor Fitzgerald, Windows on the World, Marsh, Aon, Sandler O'Neill,
Fiduciary Trust, Keefe Bruyette & Woods, Fuji Bank) named no source for any of
them, so no row is `corroborated` yet. Promoting a row requires a cited claim.

## Defects found in the source, and how they are handled

  - Column order differs between page generations. cnn_t1 and cnn_t2 are
    Tenant | SF Leased | Industry | Floor; cnn_t4, t5, t6 and t7 are
    Tenant | Square Feet Leased | Floor | Industry. The parser reads the order
    from each table's header row and records it in buildings[].column_order
    (P-010). The superseded wtc_tenants.json assumed the t1 order for all six
    pages and therefore has floor and industry swapped on every one of the 49
    wtc4/5/6/7 rows (not "a handful of rows with a column shift").
  - Missing values are empty <td> cells, never absent cells. Every data row has
    exactly four cells. Blank industry stays null, blank or "N/A" square footage
    stays null with the verbatim text in sq_ft_raw (P-011, P-016).
  - Tables end with trailing all-empty rows (t1: 4, t4: 2, t5: 2, t6: 3, t7: 2).
    Dropped and counted in buildings[].padding_rows_dropped (P-012).
  - Floor cells mix integers, ranges ("94-97"), comma lists, and the codes CNCR,
    LBBY, BSMT, GRND, LL, PLAZ. Ranges are expanded inclusively; codes are kept
    as codes (P-013). No unresolved floor token exists in this capture (P-014).
  - cnn_t2 row 2 is a row whose tenant cell reads "CINDE" with no other data,
    directly under "Continental Insurance Company". It is kept verbatim as
    wtc2-002 with raw_cells attached and flagged for human review (P-015). It
    is not merged, not dropped, and not treated as a floor token.
  - Tenant names are the source's spelling, including its errors (for example
    "Sandler O'Neil"). Nothing is normalised (P-018).

## DO NOT USE

The floor-by-floor tables that surface in search results on Grokipedia.
Wikipedia's own tenant tables were revision-deleted in Nov 2023 and the pages
merged to a 2.8KB stub in Aug 2024. Grokipedia is an AI-generated fork of the
removed content and is not a citable source.
